# 大人の漢字書き順 — Web版

読めるけれど書けない漢字を、書き順アニメーションとなぞり書きで練習するWebアプリです。参照のiPhone版と同じ57語・重複なし100字を収録しています。

## 機能

- 漢字・読み（ひらがな／カタカナ）検索、カテゴリー絞り込み
- 画ごとの書き順アニメーション、再生／一時停止、再生速度、1画ずつ進む、最初に戻す
- 指・ペン・マウスでのなぞり書き、1画戻す、消去、見本の表示切替
- 文字ごとの練習済み記録（ブラウザのlocalStorage）
- 見本なしテスト：100点満点の採点、合否、改善点、筆跡とお手本の重ね合わせ
- 自己ベスト・挑戦回数の保存、100字の合格コレクション（銅80点・銀90点・金95点）
- 金・銀・銅それぞれのメダル演出、朱印による自己ベスト更新表示、スコアのカウントアップ
- スマートフォン・タブレット・PC対応。アカウント・広告・外部API不要

採点はKanjiVGのお手本との一致度を評価するもので、書道の美しさの判定ではありません。練習と合格は別記録です。記録の端末間同期はありません。初回のページ・データ読み込みには通信が必要です。

## チャレンジの採点

練習画面の「見本なしで挑戦」からテストへ進みます。テスト中は見本・答えの漢字・文字タブを隠し、採点後に答えと比較できます。途中で画面を離れたり再読み込みした場合は未採点の筆跡を破棄し、挑戦回数には加算しません。

描画中に入力の捕捉が外れても筆跡を保持し、ウィンドウ内で移動・終了イベントを追跡します。OSなどによって入力が中断された場合は線を点線で残して通知し、「ひとつ戻す」で書き直せます。中断された線が残っている間は採点しません。

入力とお手本を画ごとに等間隔32点へ再標本化し、109×109座標のまま比較します。位置・拡大率の自動補正は行いません。形・位置60点、対応する線分の方向30点、画数10点で算出します。合格には80点以上、画数一致、各画の座標誤差RMSが12以下、各画の方向一致率50%以上、明確な画順違いがないことが必要です。条件未達のスコアは最高79点です。

方向一致率は対応する線分のコサイン類似度（逆方向は0）を平均します。各入力画が他の画と明確に近く一致する場合は画順違いとして扱います。点だけの入力や中断されたタッチは合格にしません。判定には資料による字体・書き順の違いや、指・マウスの精度差という限界があります。

チャレンジ記録は `kanji-challenge-v1` に保存します。従来の `kanji-practice-v1` は保持し、既存の練習済みを自動的に合格扱いにはしません。保存が使えない場合も、そのページを開いている間は練習できます。

合格時は、金の箔と紙片、銀の光輪、銅の押印をモチーフにした演出を表示します。自己ベストの朱印は過去の得点を実際に上回った場合のみ表示し、初回や同点では更新扱いにしません。演出は自動的に終了し、OSの「動きを減らす」設定では静止表示と最終スコアを即時表示します。音は再生しません。

## 起動・確認

Python 3 と Node.js 18以降を使用します。npmパッケージのインストールは不要です。

```sh
cd /workspace/stroke-order
npm start
```

開発サーバーのポートは4173です。別のターミナルで検証します。

```sh
npm test
npm run build
```

Playwright Python と Chromium が入っている環境では、開発サーバーを起動したままブラウザ操作テストも実行できます。このクラウド環境には両方が用意されています。

```sh
python3 tests/browser_smoke.py
python3 tests/browser_challenge.py
python3 tests/browser_input.py
python3 tests/browser_achievements.py
```

Chromiumの場所が異なる場合は `CHROMIUM_PATH`、配信先が異なる場合は `APP_URL` を指定できます。実機でのSafari・iOS確認は別途必要です。

## Web公開

`npm run build` で生成される `dist/` の中身を、静的サイトを扱うホスティングサービスに配置します。サーバー側プログラム・データベース・APIキーは不要です。相対パスとハッシュによる画面遷移を使用し、サブディレクトリ配下でも動作します。

### GitHub Pages

1. このプロジェクトのファイルをGitHubリポジトリの公開用ブランチにコミット・pushします。
2. リポジトリの Settings → Pages → Build and deployment で **Deploy from a branch** を選びます。
3. pushしたブランチと **/(root)** を選択して保存します。
4. GitHubに表示された公開URLを開き、検索・再生・なぞり書きを確認します。

ルートのファイルを直接配信できるので、GitHub Pagesではビルド設定は不要です。このリポジトリはmainのルートから公開しているため、検証後にmainへpushすると更新されます。Netlifyなどに手動アップロードする場合は `dist/` を使います。

## 書き順データ

`data/glyphs.json` は固定リビジョンのKanjiVGから抽出したSVGパスを同梱しています。通常の起動・ビルド・テスト時にネットワーク取得は行いません。再生成する場合のみ、以下を実行します。

```sh
python3 scripts/prepare_data.py
```
